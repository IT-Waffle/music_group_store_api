# Frontend handoff: просмотры, комментарии и изменения API (ноябрь 2026)

Короткая выжимка того, что frontend должен сделать или учесть. Полные контракты —
в [`api-usage.md`](api-usage.md) (раздел 10 — Engagement API) и
[`music-api-frontend.md`](music-api-frontend.md).

Все изменения API **обратно совместимы**, кроме двух сужений в п. 6 (текущий
frontend их не использует — проверено по production-бандлу).

## 1. Просмотры

**Что появилось.** Поле `view_count` (целое, ≥ 0) во всех ответах работ
(`/catalog/products`), треков и клипов (`/music/tracks`, `/music/clips`,
включая вложенные `clips[]`), публичных и админских.

**Как засчитывать.**

```http
POST /api/v1/engagement/{product|music_track|music_clip}/{id}/views
```

Без тела и без токена. Ответ `{"view_count": n}` можно сразу показать.

**Когда вызывать** (согласовано с заказчиком: просмотры неуникальные, лимитов
нет):

1. Карточка в списке **впервые попала в зону видимости** после монтирования —
   один вызов (`IntersectionObserver`, после срабатывания — `disconnect`).
2. Пользователь **открыл детальную страницу** — один вызов при открытии.

Повторные рендеры того же смонтированного компонента вызывать не должны —
backend считает **каждый** вызов новым просмотром и отличить ререндер не может.

Важно:

- Используется `id` (UUID), **не** `slug` — у трека тоже `id`.
- В React 18 `StrictMode` в dev монтирует компонент дважды — в dev счётчик
  растёт на 2, в production-сборке на 1. Это нормально.
- Ошибки (`404` для скрытого контента, сеть) глотать молча: счётчик не должен
  ломать страницу. Готовый пример — в `api-usage.md`, раздел 10.

## 2. Комментарии — публичная часть

```http
POST /api/v1/engagement/{type}/{id}/comments   → 202
GET  /api/v1/engagement/{type}/{id}/comments?limit=20&offset=0
```

**Форма**: два видимых поля и одно скрытое.

| Поле | Правило |
| --- | --- |
| `author_name` | обязательно, до 80 символов, одна строка |
| `body` | обязательно, до 2000 символов, переносы строк сохраняются |
| `website` | **honeypot** — скрытое поле, см. ниже |

**Honeypot** — обязательно сделать именно так, иначе антиспам не работает:

```html
<div style="position:absolute; left:-10000px;" aria-hidden="true">
  <label>Website <input type="text" name="website" tabindex="-1" autocomplete="off"></label>
</div>
```

Не `display:none` в отдельном CSS-классе с именем вроде `.honeypot` — часть
ботов это распознаёт. Значение поля отправлять как есть (у людей — пусто).

**После отправки (`202`)** показать локализованное «Ваш комментарий отправлен
на модерацию» (lv/ru/en — тексты на стороне frontend; поле `message` в ответе —
служебное, на английском). **Не добавлять** комментарий в список сразу: он
появится только после одобрения.

**Ошибки:**

| Ответ | Что показать |
| --- | --- |
| `422` | подсветить поле (пусто или слишком длинно) |
| `429` (`RATE_LIMITED`) | «Слишком много комментариев, попробуйте позже»; заголовок `Retry-After` — секунды |
| `404` (`CONTENT_NOT_FOUND`) | контент скрыт — убрать форму |
| `413` | не должно случаться при нормальных лимитах формы |

Лимит длины backend считает в символах Unicode. В JS `str.length` считает
UTF-16-единицы (эмодзи = 2), поэтому для счётчика символов используйте
`[...str].length`, а последнее слово всё равно за backend (`422`).

**Вывод:**

- `author_name` и `body` — недоверенный текст. Только как текст
  (`{comment.body}` в React). **Никогда** `dangerouslySetInnerHTML`/`innerHTML`.
- Переносы строк: CSS `white-space: pre-line`.
- `created_at` приходит в UTC с `Z` (`2026-11-10T22:33:50.704564Z`) —
  форматировать в локальное время:
  `new Intl.DateTimeFormat(lang, { dateStyle: "medium", timeStyle: "short" }).format(new Date(c.created_at))`.
- Сортировка — новые сверху; пагинация `limit`/`offset`, `total` в ответе.

## 3. Комментарии — модерация в админке

Доступ: `moderator` и `admin` (обычный Bearer-токен).

```http
GET    /api/v1/engagement/manage/comments?status=pending&limit=20&offset=0
POST   /api/v1/engagement/manage/comments/{id}/approve
DELETE /api/v1/engagement/manage/comments/{id}
```

- По умолчанию очередь `pending`, новые сверху. Фильтры: `status=pending|approved`,
  `target_type`, `target_id`.
- В элементе есть `target_title` (на языке из `Accept-Language`) — показывать,
  к чему комментарий.
- Только два действия: **Approve** и **Delete**. Delete удаляет навсегда —
  стоит спросить подтверждение. Редактирования нет.
- `notified_at`: когда ушло письмо владельцу; `null` — письма не было. Можно
  показать маленькой иконкой, необязательно.
- После approve/delete обновить счётчик/список очереди.

## 4. Email владельцу

Frontend ничего делать не должен: письмо уходит само при каждом новом
комментарии.

## 5. Загрузки в админке

- Анонимный запрос или запрос с **истёкшим** токеном на загрузку файла теперь
  получает `401` **до** передачи файла. Токен живёт 30 минут: перед загрузкой
  большого видео стоит убедиться, что токен свежий, и при `401` перелогинить и
  повторить загрузку.
- `413` бывает двух видов: `REQUEST_TOO_LARGE` (отсечено до чтения) и
  `MEDIA_TOO_LARGE` (во время чтения). Оба — «файл слишком большой».
- Лимиты прежние: картинки 10 МБ (у работ 5 МБ), аудио 100 МБ, видео 500 МБ.

## 6. Изменения существующего API

1. **Localization**: публичные `GET /localization/flat/{type}/…` и
   `/bundle/{type}` для `product`, `music_track`, `music_clip` теперь `404`
   (они отдавали тексты черновиков). Тексты контента брать из ответов
   Catalog/Music API (`title`, `description`). `ui` и `category` — без изменений.
2. **`GET /localization/translations/{id}`** теперь требует токен moderator/admin.
3. Любой обычный (не загрузочный) запрос больше 1 МБ → `413`.
4. `/docs`, `/redoc`, `/openapi.json` на production выключены. Для разработки
   используйте локальный backend.

## 7. Напоминания по уже существующему

- `is_playable: false` — не показывать плеер; даже при `true` обрабатывать
  `403 TRACK_PLAYBACK_DISABLED` при запросе аудио. Отсутствие кнопки не
  защита — backend всё равно закрывает аудио.
- URL медиа брать из поля `url`, не собирать руками.
- Решения принимать по `detail.code`, `message` — fallback.

## 8. Чек-лист для frontend перед релизом

- [ ] Просмотры: один вызов на появление карточки и один на открытие detail;
      проверено в production-сборке (без StrictMode-дублей).
- [ ] Используется `id`, а не `slug`.
- [ ] Форма комментария с honeypot `website` (вне экрана, `tabindex="-1"`,
      `autocomplete="off"`, `aria-hidden`).
- [ ] Сообщение «отправлено на модерацию» на трёх языках; комментарий не
      добавляется в список сразу.
- [ ] Обработаны `422`, `429` (+ `Retry-After`), `404`.
- [ ] Комментарии выводятся как текст, `white-space: pre-line`, дата в
      локальном времени.
- [ ] Админка: очередь pending, Approve, Delete с подтверждением, `target_title`.
- [ ] Загрузки: обработка `401` (истёк токен) и `413`.
- [ ] Нигде не используется `/localization/{flat,bundle}` для
      `product`/`music_track`/`music_clip`.
